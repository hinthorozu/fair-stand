## Findings

### F-030 — P1 — no canonical project-level Final BOM generator exists

The repository has per-module recipe lookup/expansion and the production-loaded `rawBomDebug` panel, but no canonical project-state-to-final-BOM aggregation layer was identified.

Therefore the system currently lacks one owner that can deterministically take the whole saved project and produce:

- aggregated production parts,
- module commercial items/exclusions,
- relationship/corner connector adjustments,
- unresolved-policy diagnostics.

`rawBomDebug.js` is not a substitute: it shows one selected module recipe by parsing UI text.

This is a product/BOM completion gap, not a claim that individual verified recipes are wrong.

### F-031 — P1 — relationship/corner connector parts are not derived from module relationships

The production catalog defines `connector_double` and `connector_corner`, which inherently describe relationships/junctions. Current module recipes instead embed per-module `connector_start` / `connector_single` quantities. No project relationship pass was identified that examines adjacent modules/corners and converts/shared-counts connector hardware appropriately.

A naive sum of per-module recipes therefore cannot be assumed to equal the real assembled stand connector BOM. This is precisely the class of part that A12.08 requires to be generated by relationship logic rather than arbitrary isolated module recipes.

Until a canonical relationship-BOM algorithm exists, Final BOM aggregation cannot be considered production-complete.
